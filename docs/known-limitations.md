# 已知限制清单

> 本清单区分两类：**设计上不支持**（有明确取舍，改了会破坏设计约束）
> 与**尚未实现**（计划要做，第一阶段未做）。
>
> 逐条标注了**验证方式** —— 只有实际验证过的项才写"已验证"。
> 声称支持而实际不支持的能力，比不声称支持更危险。

---

## 一、设计上不支持

> 这些是**有意为之**的取舍。改动前请先读"为什么"。

### 1.1 云端不做实时音频流处理

**结论**：云端只做意图判定、记忆检索与回复生成，不做流式 ASR/TTS。

**为什么**：端侧已经有 VAD 与 ASR，云端再做一遍会引入两倍延迟与两倍算力成本，
却换不来质量提升 —— 端侧已有上下文（断句结果、置信度）比云端重新识别更准。

**影响**：网络带宽只上行 PCM 帧，不上行原始录音；下行只有 TTS 音频片段。

**验证方式**：见 `core/edge/transport/uplink.py` 的上行消息集合。

### 1.2 端侧不做跨会话记忆

**结论**：端侧只保留当前会话的短期上下文，不做长期记忆。

**为什么**：长期记忆需要服务端存储与一致性保证，端侧本地存储换设备即丢失，
反而制造"两套记忆互相矛盾"的问题。

**影响**：换设备后聊天记录不跟随；记忆召回全部在云端完成。

### 1.3 协议不允许未知字段

**结论**：所有 schema 均设 `additionalProperties: false`。

**为什么**：多出一个字段说明两侧版本已经错位。静默忽略会让错位无法被发现，
直到某个功能莫名其妙不生效时才排查到。

**影响**：新增字段必须同时升级两侧，不能"先发后补"。

**验证方式**：`core/tests/protocol/test_cross_language_consistency.py`。

### 1.4 降级与回升都逐级进行

**结论**：不会从 `MINIMAL` 直接跳回 `NORMAL`。

**为什么**：网络抖动会让状态在两个档位间反复横跳，逐级回升能显著减少横跳次数。

**影响**：网络恢复后需要几轮成功才回到正常档位 —— 这是有意的延迟。

**验证方式**：`core/tests/edge/degrade/test_policy.py`（`DegradePolicy`）。

### 1.5 画像增量超限是"拒绝"不是"截断"

**结论**：超过 8192 字节的画像增量被整条丢弃。

**为什么**：截断后的画像会让用户模型处于"半新半旧"状态，且**无法察觉** ——
比明确失败更难排查。

**影响**：单次画像下发量有上限，大批量更新需分多次。

**验证方式**：`core/tests/edge/transport/test_control.py`。

### 1.6 事实性请求端侧不作答

**结论**：端侧识别出事实性请求后只做引导，不生成任何具体事实。

**为什么**：陪伴场景下编造具体的人名、地点、日期、数值会被用户当成真实记忆。

**影响**：端侧多一跳往返（要上云求证）。

**验证方式**：`core/tests/edge/dialog/test_factual.py`（`FactualGuard`）。

### 1.7 本地应答不伪装成云端回复

**结论**：端侧本地生成的应答带 `source=LOCAL` 标记，**不会**混进云端回复流。

**为什么**：用户在离线时听到机器人的回话，若不知道那是本地兜底产生的，
就会以为"云端还在正常服务"，从而对服务可用性产生错误判断。
标记放在应答对象上而不是改写文本 —— 改写文本会污染语音合成的输入，
也会被回复长度门禁误判。

**影响**：调用方需要自己读 `LocalReply.source` 才能区分来源；
云端回复（`TextReply`）没有这个字段，两者结构不同。

**验证方式**：`core/tests/edge/dialog/test_responder.py`、
`core/tests/edge/test_simulator.py`。

### 1.8 情感判定用关键词表而非模型

**结论**：端侧情感标签由关键词表判定，不做模型推理。

**为什么**：端侧要在没有模型、甚至没有网络的机器上工作，
关键词表零依赖、零延迟；情感判定的容错度也远高于事实性判定 ——
判错一桶的后果只是话术语气略偏，而事实性判错会导致编造。

**影响**：长句或反讽的情绪可能判不准。命中时取**最长关键词**所在桶，
因此"今天不开心"落到 `sadness` 而非 `joy`。

**验证方式**：`core/tests/edge/dialog/test_emotion.py`。

## 二、尚未实现（第一阶段范围外）

> 这些是**计划要做但还没做**的。列在这里是为了让接手的人知道边界在哪。

### 2.1 云端鉴权

**状态**：**未实现**。上行 WebSocket 目前不校验任何凭据。

**影响**：任何能连到端口的客户端都能建立会话。

**计划**：见 OpenSpec 任务 6.2。

### 2.2 会话上下文的 Redis 存储与一致性哈希环

**状态**：**部分实现**。`SessionRegistry` 用进程内 `ConcurrentHashMap` +
哈希取模分片；Redis 存储与一致性哈希环未实现。

**影响**：云端多实例部署时会话状态不共享；处理单元数量变化时几乎所有会话会重新映射。

**计划**：见 OpenSpec 任务 6.3。

### 2.3 处理单元失效后的会话重路由

**状态**：**未实现**。

**影响**：处理单元崩溃后，其上的会话无法自动迁移。

**计划**：见 OpenSpec 任务 6.4。

### 2.4 心跳超时的定时扫描

**状态**：**部分实现**。`onHeartbeatTimeout` 方法已实现并有测试，
但**驱动它扫描超时会话的定时器未实现**。

**影响**：实际运行中会话不会因心跳超时被自动回收（只有显式 `end` 消息会回收）。

**计划**：见 OpenSpec 任务 6.5。

### 2.5 下行语音流式下发

**状态**：**部分实现**。协议侧的编排与端侧接收已完成并有测试：
- 云端：`DownlinkPublisher`（首包/末包标记、序号连续、发布前协议校验）；
- 端侧：`DownlinkClient`（先校验再分派、丢弃计数、首包延迟测量）；
- 实测：端侧能收到云端下发的文本回复，回复与请求一一对应。

**未完成**：
- **云端的回复内容是占位实现**（`DownlinkReplyService.buildText` 返回固定话术），
  真实回复需由意图三级判定与记忆检索生成（任务 7.1–7.8、9.1–9.10）；
- **没有真实的 TTS 音频**：云端不下发 `voice-chunk`，只下发 `text-reply`。
  语音片段的协议路径已实现但未接入真实音频源。

**影响**：机器人会回话，但**回的是固定话术**，不是基于上下文与记忆的回应。
用户能体验到"有来有回"，体验不到"它记得我"。

**计划**：见 OpenSpec 任务 6.6、7.x、9.x。

### 2.6 云端意图判定、多轮澄清与子智能体编排

**状态**：**未实现**。OpenSpec 第 7 组全部未做。

**影响**：长尾意图上云后没有实际处理能力。

**计划**：见 OpenSpec 任务 7.1–7.8。

### 2.7 记忆装配（第 9 组）

**状态**：**未实现**。

**影响**：云端没有记忆能力；`agent-memory-kb` 的资产只做了复制，未接入调用链。

**计划**：见 OpenSpec 任务 9.1–9.10。

### 2.8 评测与门禁（第 10 组）

**状态**：**未实现**。

**影响**：**目前没有任何可复现的指标基线**。第一阶段交付的是链路骨架与协议契约，
不是可对外展示的性能数字。

**计划**：见 OpenSpec 任务 10.1–10.7。

### 2.9 设备侧固件与 OTA

**状态**：**未实现**。`device-ref/` 目前只有说明文档。

**影响**：真机形态未经任何验证。

**计划**：见 OpenSpec 第 11 组。

### 2.10 真实语音交互

**状态**：**未实现**。模拟端用脚本驱动的识别结果，没有真实麦克风采集，也没有 TTS 播放。

**影响**：**没有真实语音可用**。这直接决定了本阶段不能宣称"语音陪伴"能力 ——
只能宣称"端云协议链路与状态机骨架"。

**计划**：第二阶段。

### 2.11 真实模型驱动的端侧能力

**状态**：**未验证**。`faster-whisper` 与 `llama-cpp-python` 已列入依赖，
但**未在本机跑过真实模型的推理**。

**影响**：端侧识别耗时、端侧生成速度等指标**没有实测值**。

**计划**：第二阶段，需在 `core/models/` 备齐权重后测量。

## 三、验证状态总览

| 类别 | 项数 | 验证方式 |

| 设计上不支持 | 8 | 每项有对应单元测试 |
| 尚未实现 | 11 | 标注 OpenSpec 任务号 |
| 已实测的端到端链路 | 2（在线双向 / 离线本地） | 见下方 |

### 已实测的端到端链路

**双向链路**：端侧模拟音频 → 帧组装 → VAD → 断句 → 识别 → 意图判定 →
WebSocket 上行 → 云端协议校验 → 会话注册 → 云端回复 → 下行 WebSocket →
端侧协议校验 → 分派 → 收到回复。

**验证命令**：

```powershell
powershell -ExecutionPolicy Bypass -File core\scripts\start.ps1
F:\tools\python313\python.exe -m core.edge.simulator --url ws://127.0.0.1:8080/voice/uplink --rounds 3
```

**判定标准**：

1. 云端日志出现"会话已注册"与"会话已回收"；
2. 端侧日志显示三条路径（本地执行 / 事实性引导上云 / 长尾上云）分别命中；
3. **上行请求数与收到的回复数一一对应** —— 多一条说明本地意图不该上行，
   少一条说明上行失败了。

**离线链路**：云端不可达 → 端侧降级到 `OFFLINE` → 情感判定 → 本地话术应答 →
标记为本地产生 → 逐级回升的降级状态机就位。

**验证命令**：

```powershell
F:\tools\python313\python.exe -m core.edge.simulator --url ws://127.0.0.1:1/voice/uplink --rounds 2
```

**判定标准**：

1. 端侧日志出现"降级为 OFFLINE，转入本地陪伴模式"；
2. 出现"本地产生应答=…（情感=… 离线=True 来源=LOCAL）"；
3. **进程退出码为 0** —— 离线时崩溃等同于设备坏掉。

**未覆盖**：真实语音、真实模型、真实 TTS 音频、云端回复内容（当前是占位话术）、
性能指标。
