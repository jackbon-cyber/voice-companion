# deploy —— 公司私有部署层

> **本目录不属于开源仓库 `core/`。**
> 公司内网的模型网关适配、GPU 编排、监控接入等私有实现放在这里，
> `.gitignore` 已排除本目录的全部内容（`deploy/*` 除本 README）。

## 目录用途

| 子目录 | 用途 |
|---|---|
| `gateway/` | 内网模型网关适配层：把公司内部统一的模型服务协议适配成 `core/cloud` 期望的接口。 |
| `gpu/` | GPU 编排：模型实例的部署、扩缩容、显存分配。 |
| `monitoring/` | 监控接入：指标采集、告警规则、值班看板。 |

## 硬性约束

1. **业务逻辑不得下沉到本目录。**
   本目录只做**基础设施适配**——协议转换、资源编排、监控接入。
   任何会改变业务语义（意图判定、回复生成、记忆读写策略）的代码，
   必须落在 `core/` 并走对应的评审。

   *为什么*：`deploy/` 不在开源仓库里，也不进评审流程。
   业务逻辑沉在这里，��仓库的改动就绕过了所有质量门禁 ——
   公司内部单点积累出与开源实现不一致的"影子版本"。

2. **本目录不得直接依赖 `core/` 的内部实现细节。**
   与 `core/` 的交互只走已发布的协议（见 `docs/interface-contract/README.md`）
   或明确标注为扩展点的接口。

3. **凭据一律走环境变量**，仓库内不出现真实密钥。

## 与开源仓库的协作方式

私有实现通过三条路径回流到 `core/`：

| 私有实现 | 回流方式 | 判定标准 |
|---|---|---|
| 网关协议转换 | 抽成 `core/cloud` 的可插拔适配器 | 转换逻辑与业务逻辑分离，有独立测试 |
| GPU 调度策略 | 只保留策略接口在 `core/`，实现在本目录 | 接口稳定，实现可替换 |
| 监控埋点 | 只保留指标定义在 `core/`，采集实现在本目录 | 指标名与口径由 `core/` 定义 |

判断标准很简单：**这段代码换个公司还要不要改？**
要改的说明它是业务逻辑，应该进 `core/`；
不用改的说明它是基础设施适配，留在本目录。
