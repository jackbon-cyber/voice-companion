# 记忆检索阈值推导实验

> 这些脚本是**相关性下限 0.544 这个数字的证据链**。
> 没有它们，0.544 就只是一个魔法值 —— 换批数据时没人知道该怎么重算。

## 为什么这些脚本要入库

阈值写在 `MemoryRelevancePolicy.MIN_RELEVANCE_SCORE` 里，
但**这个数字本身不是设计出来的，是测出来的**。

如果只交代码不交实验：
- 换一批数据时，只能靠"感觉调一下"；
- 没人能验证 0.544 是推导出来的还是拍出来的；
- 评审时无法判断它是否过拟合。

|---|---|---|

| `intent_pooling_experiment.py` | 换池化会伤到意图维度吗？ | 不会，两者都是 15/15 |
| `verify_pooling.py` | 服务里的向量和本地现算的口径一致吗？ | 一致（否则上面的对比不成立） |

## 关键结论摘录

### 阈值随嵌入方式变化（最容易踩的坑）

同一份留出集，两种嵌入方式测出的阈值**不同**：

| 嵌入方式 | 答对时最低得分 | 无答案时最高得分 | 中点 |
|---|---|---|---|
| 整句嵌入 | 0.4478 | 0.5029 | **不可分** |
| **分片嵌入** | 0.5480 | 0.5402 | **0.544** |

分片把长记忆的得分整体抬高（0.5145 → 0.6176），**分布平移了**。
沿用旧阈值等于**拿一把尺子量另一把刻度**。

**留出集推导**（`holdout_threshold.py`，整句嵌入）：

```
答得对时的最高得分下界 = 0.5313
库中无答案时的最高得分上界 = 0.5268
=> 合法取值区间 (0.5268, 0.5313]，取中点 0.529
```

**留出集推导**（`chunked_threshold.py`，分片嵌入）：

```
答对时的最低得分 = 0.5480
无答案时的最高得分 = 0.5402
=> 合法取值区间 (0.5402, 0.5480]，取中点 0.544
```

**为什么不用评测集推导**：评测集（`core/eval/memory_answer-eval.txt`）
就是门禁要用的那批数据。在它上面挑一个"能过线"的阈值是**拿答案调答案**，
换批数据立刻失效。留出集的**语料与评测集相同、问句全部重写**，
因此阈值是独立推导出来的。

### 分片嵌入 vs 混合检索（为什么选了分片）

问题：用户在真实对话里说的是完整句子。
"我妈妈叫李芳，她很爱我，每天都给我做饭，还总提醒我早点休息"（29 字）
与"我妈妈叫什么"的语义距离远大于"我妈妈叫李芳"（6 字）与它的距离，
整句嵌入得分只有 0.5145，低于相关性下限 → **机器人对刚听用户说过的事说"没有记录"**。

两种候选方案在同一份语料上的实测：

| 方案 | 改变什么 | 实测结果 |
|---|---|---|
| **混合检索**（词元粗筛 / 分级降级 / 主体优先） | **候选排序** | 四种策略**全部不可分**；词元粗筛还会误杀"语义相近但用词不同"的正确答案 |
| **分片嵌入** | **候选的向量表示** | **答错 6 → 1 条**，长记忆得分 0.5145 → 0.6176 |

关键区别：稀释发生在**向量层面**，排序层面救不回来。

**分片的代价**：片段级语义区分变弱（留出集唯一错例是
"我眼下在忙着准备哪件事"命中了片段"我表姐在南京工作"）、
存储量翻倍、新旧数据并存（存量数据无需迁移）。

**被实测否掉的方案**（留在仓库里是为了说明"为什么没有"）：

1. **区分度判据**（第一名与第二名得分差太小就拒答）—— 不可分，领先幅度反向重叠。
2. **查询侧加检索指令前缀** —— Top-1 从 12/13 掉到 11/13，代价大于收益。
3. **更小的下限 0.476** —— 覆盖率更高，但 14 条答不上的问句里有 11 条被当成答案，
   **系统开始编造**。
4. **混合检索** —— 见上，四种策略全部不可分。

## 脆弱性

0.544 两侧只有 **0.0039** 的余量，样本量只有 13 + 13 条。
这是**当前实测下的取值，不是普适结论**。

评测集或留出集扩充后**必须重跑 `chunked_threshold.py` 并重新推导**，
不能沿用现值。换一种嵌入方式（换模型、换池化、改分片规则）
同样必须重推 —— **阈值是嵌入方式的函数，不是记忆系统的常数**。

检索能力提升（更大的嵌入模型、混合检索、query 改写）
会让缝隙变宽，届时应**上调覆盖率门禁、而不是下调相关性下限**。

## 剩余拒答样本的性质（下一轮的抓手）

`locate_refusals.py` 在评测集上逐条复算，定位到被拒答的 3 条：

| 问句 | 期望 | Top-1 实际 | 得分 | 距下限 0.544 |
|---|---|---|---|---|
| 我接下来有什么安排 | 我下个月要参加同学的婚礼 | **完全正确** | 0.4967 | -0.0473 |
| 我最近在忙什么 | 我正在准备考研 | **完全正确** | 0.4852 | -0.0588 |
| 我有什么饮食禁忌吗 | 我对芒果过敏 | 错（命中"我最爱吃酸菜鱼"） | 0.4708 | -0.0732 |

**关键结论**：被拒的 3 条里有 **2 条的 Top-1 就是正确答案** ——
它们不是"检索不到"，而是**得分落在可分缝隙之外**。
换句话说，剩余缺口卡在**得分分辨率**上，不是语义匹配上。

**但不能下调阈值**：拒答侧的最高得分是 0.5246（"我同事叫什么"），
**高于上面两条被拒的正确答案得分**。下调到 0.47–0.49 就会把
"库里没有答案"的问题判成可答 —— 实测下限 0.476 时 14 条答不上的问句里
有 11 条被当成答案，**系统开始编造**。

**所以正确的方向是抬高分分辨率**，而不是放松准入：
更大的嵌入模型、混合检索（用于把候选集缩小而非改变排序）、
query 改写 —— 这些能让"答得出"与"答不出"的缝隙变宽。
缝隙变宽之后，应当**上调覆盖率门禁**，而不是下调相关性下限。

## 踩过的坑：语料自相矛盾会让一切实验失效

两版实验都出现了"所有策略都不可分、答错数暴涨"的怪象。
根因都是**语料本身自相矛盾**：

- 第一版把同一主题的长短两版同时放进语料
  （"我奶奶住在苏州" 与 "我奶奶住在苏州老家那边…"），
  问句该匹配哪条？**无解**；
- 第二版把"库里确实有答案"的问句（"我养的第一只仓鼠叫什么"，
  库里存着"一只叫团子一只叫糯米还有一只叫芝麻"）误放进了"库里没有答案"组，
  它的得分高达 0.6786，把"无答案侧上界"顶了上去。

**教训**：跑阈值实验前，先确认语料**每个主题有且只有一条记忆**，
且"无答案"组里的每条问句在库中**确实无解**。
否则测出来的是语料缺陷，不是检索能力。
